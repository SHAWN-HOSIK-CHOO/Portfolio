# [전투 기획서] 감정 시스템 및 액션 메커니즘

## 1. 핵심 전투 및 빌딩 매커니즘

플레이어의 전투 빌드는 **[무기 고유 슬롯 효과] + [무기 슬롯에 스킬 장착] + [3개 에이전트의 스킬 및 스탯의 조합]** 의 3가지 축이 결합하여 완성된다.

```text
[ 무기 슬롯 고유 효과 ]  +  [ 액션 노드 스킬 장착 ]  +  [ 에이전트 3체의 스탯/보유 스킬(에이전트 1체 당 스킬 4개) ]
(슈퍼아머, 체력 회복 등)   (약/강공, 패링, 액티브)    (에이전트 각 스텟의 평균값 + 보유 스킬(패시브/액티브 무관))
           └──────────────────────────┬──────────────────────────┘
                                      ▼
ex. 타격할 때마다 체력을 회복해주는 약공격 1타에는 SurpriesStrike 스킬을 장착하고, 발사체 속도 증가 효과가 있는 약공격 2타에는 AngerShoot이라는 스킬을 장착
```                                 

## 2. 에이전트(Agent) 인지 상태 정의

플레이어를 제외한 모든 적 에이전트, 기믹, 환경 요소는 하나의 지배적인 감정 상태 또는 무감정 상태를 유지한다.

* **기초 감정(Base Emotions) 제약**: 각 에이전트는 설계 목적에 따라 수용 가능한 기초 감정이 고정된다.
* **해킹 저항**: 기초 감정 범주를 벗어난 감정 주입 시, 에이전트 인지 회로가 불법 데이터로 간주하여 무시한다. 즉, 기초 감정에 해당하지 않는 감정은 점수가 쌓이지 않는다.
* **점수(EP) 획득**: SkillInfo.json에 적힌 EPValue만큼 스킬 사용시 획득한다.

## 3. 적 에이전트 행동 파라미터 (행동을 선택하는 기준) 및 지배적 감정 진입

적 에이전트의 감정 상태는 행동 결정 알고리즘의 가중치(`E_Modifier`)를 변화시키며, 조건 충족 시 지배적 감정 상태로 폭주한다.

### 가중치 및 수치 연산식

- **감정 강도 비율 (`I_i`)**: 현재 축적된 감정 포인트(EP)를 한계치 대비 비율로 정규화한다.

  ```math
  I_i = \frac{EP_i}{EP_{\max}}
  ```

  단, `EP_max = 2000`이다.

- **파라미터 보정 합산량 (`Delta_W_total`)**: 각 감정의 강도(`I_i`)와 테이블의 파라미터별 보정치(`Delta_W_i_param`)를 곱하여 합산한다.

  ```math
  \Delta W_{\text{total}} = \sum_{i=1}^{m} \left( I_i \times \Delta W_{i,\text{param}} \right)
  ```

- **가중치 보정식 (`E_Modifier`)**:

  ```math
  E_{\text{Modifier}} = \text{Clamp}\left(1.0 + \Delta W_{\text{total}},\, 0.1,\, 2.5\right)
   ```

  ※ 감정 중첩 시 가중치가 음수 이하로 떨어지거나 과도하게 폭증하는 현상을 방지하기 위해 최소 0.1 ~ 최대 2.5 범위로 제한한다. 단, 지배적 감정 진입 시 상한을 3.0으로 확장한다.

- **행동별 최종 가중치 (`W_final`)**:

  ```math
  W_{\text{final}} = W_{\text{base}} \times E_{\text{Modifier}} \times M_{\text{Dominant}}
  ```

  ※ 일반 상태: `M_Dominant = 1.0`, 지배적 감정 폭주 상태: `M_Dominant = 1.5`

- **행동 선택 확률 (`P(Action_k)`)**: 전체 후보 행동(`N`) 간 확률 분포를 정규화한다.

  ```math
  P(\text{Action}_k) = \frac{W_{\text{final},k}}{\sum_{j=1}^{N} W_{\text{final},j}}
  ```

### 지배적 감정 진입 조건

1. **EP 한계 도달**: 단일 감정 EP **2000점** 도달 시 즉시 진입 ($M_{\text{Dominant}} = 1.5$ 및 가중치 상한 3.0 적용).

## 10. 플레이어 - 지배적 감정(LB+RB) 및 점수 소모(Burn) 스탯 폭발

플레이어는 수집한 EP를 바탕으로 원하는 타이밍에 폭주 상태에 진입하여 스킬을 난사하고 스탯을 증폭시킨다.
UI연출, VFX, SFX를 동원해 **엔진에 연료를 태운다**는 느낌을 줘야한다.

* **발동 방식**: **[LB + RB]** 동시 입력으로 진입.
* **유지 시간**: **15초 고정**
* **스킬 변환 및 EP 소모**:
  * 15초 동안 무기에 장착된 스킬들이 '혼합 감정 스킬'로 변환됨.
  * 쿨타임이 없는 약/강공격에 장착 가능한 스킬들은 보통 low~mid EP(50~250)를 연타로 태우고, 액티브 1/2 슬롯에 장착 가능한 스킬은 high EP(500~1000)를 한 번에 태움.
* **스테이지 내 영구 스탯 증가**:
  * 15초 동안 혼합 감정 스킬을 사용하여 **소모(Burn)한 누적 점수가 2000점에 도달할 때마다**, 해당 감정에 대응하는 현재 최종 스탯이 스테이지 내에서만 영구적으로 증폭됨.
  * 기본값이 0인 스탯은 사전 장비/패시브/버프 세팅으로 0 이상을 만들어야 2배 뻥튀기 효과를 적용받음.

### 감정별 점수 소모(2000점) 시 영구 상승 스탯 테이블

## 11. 스킬 장착 및 속성 메커니즘

* **출력 형태**: 타격 강화(기본 애니메이션 유지 + 속성/효과 추가) / 발사체(Notify 시점 공격 수행).
* **혼합 전이 규칙**: 지배적 감정 진입 시 장착된 스킬의 GE에 따라 혼합 스킬로 변환 (별도 데이터 테이블 관리). 물리 및 `_Pure` 스킬은 변환 제외.
* **감정 속성별 고유 특징**: 8개의 감정마다 가지는 고유의 특징. 혼합 스킬은 두 감정의 특징을 모두 가진다 (ex. Love(Joy + Trust) 스킬은 Joy와 Trust 특징을 모두 가짐)
  * **Joy**: 다단히트 스킬 사용 시 성공확률 -20%, 지배적 감정 중 미적용, DamagePercentagePlus이 1 증가된 데미지를 가함
  * **Sadness**: 느린 공격 속도, 넓은 공격 범위 (`AttackRangeMultiplier` 적용)
  * **Fear**: 자가 자원 소모 (스킬 사용 시 최대 HP의 1% 감소)
  * **Trust**: 필중 원거리, 낮은 계수 (성공확률 +20%)
  * **Anticipation**: 낮은 명중률, 높은 치명타 데미지 (크리티컬 확률 -10%, 크리티컬 데미지 +25%)
  * **Surprise**: 랜덤 CC기 부여
  * **Anger**: 버프 효율 증폭
  * **Disgust**: 타격 성공 시 DoT 피해 (3초간 1초마다 최대체력 비례 데미지)

## 12. 무기 및 스탯 연산 시스템

무기는 플레이어의 감정 데이터를 변환/증폭하는 매개체이다.

* **스탯 부스트 연산 공식**: $\text{최종 스탯} = (\text{에이전트 3인의 스탯 총합}) \times \text{무기 배율 보너스}$
* **감정 계산 알고리즘**: 무기 옵션으로 특정 감정 EP 수급 증폭/감소 및 차단(0점 고정) 가능.
  * *예시 (무한한 쾌락의 검)*: Joy, Surprise, Anticipation 획득량 3배 / Sadness 획득량 0 고정.
* **스킬 슬롯 규칙**: 무기 몽타주 내 각 타격 단계를 독립 슬롯으로 취급하여 스킬 장착.
* **무기 고유 기능**: 타격 단계별 독립 특수 효과(예: 강공격 성공 시 HP 회복) 및 기본 내장 감정 속성 보유.

## 13. 플레이어 유닛 및 융합 시스템

* **듀얼 컴뱃**: 플레이어 + 장착 에이전트 한 체를 스테이지에 스폰해서 협동 전투 수행.

## 14. 스태거(Stagger) 및 강인도(Poise) 연산 시스템

모든 캐릭터의 최대 스태거(`MaxStagger`) 수치는 **100**으로 고정하며, 피격 시 가해진 데미지(`Damage`)와 피격자의 강인도(`PoiseLevel`)를 조합하여 스태거 데미지(`StaggerDamage`)를 산출 및 차감한다.

### 가중치 및 수치 연산식

* **스태거 데미지 연산식 ($\text{StaggerDamage}$)**:
  $$\text{StaggerDamage} = \left( \text{BaseCoefficient} \times \sqrt{\text{Damage}} \right) \times \left( \frac{K}{K + \text{PoiseLevel}} \right)$$

* **파라미터 정의**:
  * **$\text{Damage}$**: 피격자에게 가해진 최종 데미지 수치 (1 ~ 수천 단위).
    * *제곱근 보정을 적용하여 초고대미지 스킬 공격 시 스태거 수치가 과도하게 오버킬되는 현상을 방지(한계 효용 감소).*
  * **$\text{PoiseLevel}$**: 피격 대상의 강인도 수치 (수치가 높을수록 받는 스태거 데미지 감소).
  * **$\text{BaseCoefficient}$ (기본 가중치 계수)**: **2.0**
  * **$K$ (강인도 감쇄 상수)**: **100**
    * *PoiseLevel = 100$일 때, 받는 스태거 데미지가 정확히 50%로 감쇄.*

### 스태거 데미지 수치 시뮬레이션 예시 ($BaseCoefficient = 2.0$, $K = 100$)

| 공격 종류 | 데미지 | 일반 몹 (`Poise 0`) | 정예 몹 (`Poise 50`) | 보스 몹 (`Poise 150`) |
| :--- | :---: | :---: | :---: | :---: |
| **약공격** | 100 | **20.0** (5타 시 그로기) | **13.3** (8타 시 그로기) | **8.0** (13타 시 그로기) |
| **강공격** | 400 | **40.0** (3타 시 그로기) | **26.7** (4타 시 그로기) | **16.0** (7타 시 그로기) |
| **필살기** | 1,600 | **80.0** (2타 시 그로기) | **53.3** (2타 시 그로기) | **32.0** (4타 시 그로기) |
| **초고대미지** | 5,000 | **141.4** (1타 그로기) | **94.3** (2타 그로기) | **56.5** (2타 그로기) |

### 메커니즘 및 처리 흐름

1. **실시간 데미지 연동 연산**: `CharacterBaseAttributeSet`의 `PostGameplayEffectExecute` 시점에서 HP 데미지가 적용될 때, 피격자의 `PoiseLevel`을 참조하여 `StaggerDamage`를 즉시 수식 계산 후 `CurStagger`를 차감한다.
2. **스태거 브레이크(Stagger Break) 판정**:
   * 피격자의 `CurStagger`가 **0 이하**가 되는 순간, 시스템은 피격 대상에게 `Event.Stagger.Break` GameplayEvent를 전송한다.
   * 이벤트 수신 시 대상 캐릭터는 그로기/스태거 어빌리티(`GA_Stagger`)를 즉시 실행한다.

## 15. 스킬 데이터 구조 (SkillInfo.json 명세)

스킬 시스템은 별도의 JSON 테이블을 통해 각 스킬의 메타데이터와 동작 방식을 관리한다. 아래는 단일 스킬(`AngerStrike`) 데이터의 예시와 각 항목에 대한 설명.

### 15.1. 단일 스킬 JSON 예시 (`AngerStrike`)

```json
{

    "SkillType": "Active",
```

### 15.2. 스킬 파라미터 세부 명세

* **Name**: 스킬의 고유 이름.
* **PC_AttackInfo**: 플레이어(PC)의 특정 슬롯에 장착될 때의 정보 및 소모 칸 수를 나타낸다. (Attack Array가 2개 이상일 경우 PC의 현재 타격 및 다음 타격 연계에 어떻게 적용될지 결정.)
* **SkillType**: 액티브(Active)와 패시브(Passive) 여부를 구분한다.
* **EPValue**: 스킬 사용 시 획득(또는 소모)하는 감정 포인트(EP)의 수치.
* **TransformInfo**: 캐릭터가 특정 **지배적 감정 상태**에 진입했을 때, 이 스킬이 어떤 스킬로 대체(변환)되는지 정의한다.
* **Attribute**: AI의 행동 결정을 위한 태그. 이 스킬이 어떤 조건(예: 근접 `Melee`, 체력 부족 `HpLow`, 타격기 `Strike` 등)에서 사용되는지 명시한다.
* **AbilityAlias**: AI가 해당 스킬을 시전할 때 실행해야 할 언리얼 엔진 Gameplay Ability(GA) 클래스의 경로.
* **Cooldown / CooldownTag**: 스킬의 재사용 대기시간(초)과 이를 식별하기 위한 쿨타임 게임플레이 태그.
* **MontageIndex**: 스킬 사용 시 재생할 애니메이션 몽타주 인덱스 번호. PC를 제외한 에이전트들은 `0~8`번까지 지정된 배열을 사용한다.
  * `0`: 1타 근접 공격
  * `1`: 2타 근접 공격
  * `2`: 3타 근접 공격
  * `3`: 프로젝타일 1회 발사
  * `4`: 프로젝타일 2회 발사
  * `5`: 버프기
  * `6`: 디버프기
  * `7~8`: 캐릭터 고유 전용기
* **AdditionalSocketData**: 기본으로 지정된 소켓(예: `Projectile_Socket_01`) 대신 다른 발사 소켓(예: `Projectile_Socket_04`)을 오버라이드하여 사용하고 싶을 때 지정한다.
* **Attack**: 애니메이션 노티파이(Notify)와 연동되는 이벤트 묶음. 상세한 내장 이벤트 설계는 별도의 개발 매뉴얼을 따른다.
  * **`Pre`**: 공격 준비 동작 시작 시 발생하는 이벤트
  * **`Hit`**: 실제 타격 프레임(데미지 판정 등)에 발생하는 이벤트
  * **`Post`**: 타격 이후 복귀 동작 직전에 발생하는 이벤트
